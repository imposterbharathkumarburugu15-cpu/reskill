# Locked product and next gates

The final shared brief names SOVARIX and targets real iQOO Android phones. It supersedes the earlier NEXUS TWIN name and developer-tools proposal. Gaming is one demonstration workload.

**Observe → Adapt → Model → Predict → Simulate → Decide → Act → Verify → Learn.**

| Original idea | Current delivery / next gate |
|---|---|
| Self-Optimizing Phone | Controls SOVARIX observation cost. System-wide optimization needs documented APIs. |
| Phone Future | Numerical extrapolation; real-device validation needed before accuracy claims. |
| Device DNA | Real per-context baselines and forecast-error calibration. Richer cooling/drain models need repeated comparable sessions. |
| Phone Black Box | Event timeline, minute summaries and comparison records. |
| Phone Simulator | Explicit sensitivity analysis; causal workload effects need controlled experiments. |
| Phone Autopilot | Governor, recommendations, action permissions; goal-based system control is future work. |
| Performance Stock Market / Capital | Potential UX abstraction preserved; no arbitrary percentage displayed. |
| Phone Carfax | Exportable observations; no resale/condition certification. |
| Device Insurance AI | Fauture evidence product; no underwriting or failure score. |
| Device Intelligence Network | Future opt-in research; no telemetry upload. |
| Phone Twin OS | Intelligence architecture, not a replacement operating system. |
| Local LLM | Explanation interface + deterministic fallback. Choose and benchmark a model against measured device budget later. |
| Dual-chip path | Capability selector + probe interface. Actual Q-chip SDK adapter remains pending documented access. |
| Office Kit | Export can be transferred manually; no live link or SDK integration. |

Next priorities: install on target iQOO, audit real signals, measure overhead, collect comparable sessions, calibrate forecasting and intervention effects, then evaluate a local language model. Keep the numerical engine and LLM separate.
